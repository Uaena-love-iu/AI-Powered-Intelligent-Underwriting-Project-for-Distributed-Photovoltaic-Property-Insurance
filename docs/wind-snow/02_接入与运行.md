# 接入与运行

Python 3.11～3.13。命令在交付包根目录运行。Windows示例：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r sdk/requirements.txt
.\.venv\Scripts\python.exe sdk/run_offline.py
.\.venv\Scripts\python.exe sdk/verify_delivery.py
```
离线计算只需要Pydantic及其依赖。示例不访问网络，不查真实组件型号，不写案件数据库。

## 接入既有Python系统
调用 sdk/adapter.py 的 evaluate(payload, component_record)。payload见examples/01_assess_request.json；component_record必须由服务端可信型号查询得到，不接受浏览器任意填写能力值。返回assessment和report_markdown。
适配器内部引用source/backend的app命名空间；已有同名app项目建议作为独立服务部署，避免模块名冲突。也可将app/catastrophe/front_load_screening模块按自身工程命名规范迁移，并显式适配ComponentProfile与BusinessRulesConfig，保持测试结果不变。

## 运行完整工作台快照
```powershell
.\.venv\Scripts\python.exe -m pip install -e './source[dev]'
.\.venv\Scripts\python.exe -m pip install -r source/component-model-workbench/requirements.txt
Copy-Item source/.env.example source/.env
# 在本机填写source/.env中的模型、组件查询等配置；不要共享密钥
.\.venv\Scripts\python.exe source/start_workbench.py
```
浏览器访问 http://127.0.0.1:8768/risk-lab 或 /evaluation。8768端口需空闲；不要在已有工作台运行时再启动同端口实例。源启动器在前台运行，关闭进程即停止。

## 专项接口与报告测试
```powershell
Push-Location source
..\.venv\Scripts\python.exe -m pytest tests/integration/test_unified_wind_snow.py -q
node --test tests/frontend/underwriting-report.test.cjs
Pop-Location
```
专项接口测试使用模拟provider与临时数据库，不调用真实厂家服务；Node仅用于前端报告测试，启动工作台不需要Node。

## 在已有工作台升级
source/为当前整合版本源码快照。不要盲目覆盖别人新增的业务代码：比对api/unified_risk.py、main.py、pipeline/core.py、decision/engine.py、reports/generator.py、front_load_screening目录与四个相关前端文件。数据库合并报告采用新增case_id，不修改原人工审核。迁移时保持data/rules和city数据文件相对路径，前端统一使用同一域名及端口，避免localhost与127.0.0.1分开存储历史。

新系统仅需要风雪计算时优先接SDK；需要照片、材料、人工审核和报告整合时接完整工作台API。

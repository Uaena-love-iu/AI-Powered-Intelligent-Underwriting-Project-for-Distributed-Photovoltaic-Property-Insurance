# 组件参数检索与人工补正

## 为什么要增加检索兜底

当前运行目录覆盖面有限：69 个精确列示的中国市场型号都有额定功率与正反面静载，只有 9 个记录了冰雹试验参数；该批精确匹配型号没有可自动匹配的风载或雪载参数。364 条原始参考行包含其他市场和派生型号，不能把它们近似映射到不同铭牌型号。

检索兜底的目标是更快找到原始资料并让人工补录有证据可追溯。它不把搜索摘要、相似型号或第三方页面中的数字直接作为核保参数。

## 检索顺序

1. **确认厂商和完整型号**：优先从案件型号/铭牌录入；本地精确目录可提示厂商。当前可识别的官网映射包括 JA Solar、LONGi、JinkoSolar、Trina Solar、Canadian Solar、Risen、Qcells。无法识别时由核保员填写。
2. **厂商官网精确型号资料**：用完整型号限定到已识别厂商官网域名。
3. **厂商官网系列资料**：需要填写准确系列名；不从型号后缀盲猜系列。
4. **Solar-Stack 型号页**：按完整型号检索；如有系列名，也按系列检索。打开 [Solar-Stack 光伏组件目录](https://www.solar-stack.com/en/panel)，搜索完整型号或系列，进入匹配型号后选 **Documents → Datasheet**。以 PDF 原文中列明的精确型号、版本、单位和测试条件为准，保留 PDF 原始链接。
5. **全网网页候选检索**：厂商和 Solar-Stack 检索后，系统会继续搜索全网 HTTPS 页面，不要求预先提供域名白名单。结果可能来自经销商、论坛或资料镜像，只作为线索，来源和型号都要人工核验。可选配置 `PV_COMPONENT_TRUSTED_SOURCE_DOMAINS`（逗号分隔）让指定域名先进行一次单独检索；这不会使其参数自动得到业务认可。
6. **人工补正**：核保员打开原始 Datasheet 后，将逐项读到的参数和来源链接录入工作台。未列出的参数保持空值。

搜索接口：`GET /api/v1/components/sources?model=<完整型号>&manufacturer=<厂商>&series=<系列>`。后台网页检索使用 Brave Search API；Brave 必须单独配置 `PV_COMPONENT_SEARCH_API_KEY`。配置后会运行厂商官网、Solar-Stack 和全网候选检索。不配置受信域名也可以全网检索。未配置搜索 API Key 时，接口提供 Google/Bing 浏览器检索链接、Solar-Stack 型号页和本地目录中的近似型号候选；这些浏览器页面不会由后台自动抓取，候选参数也不会自动用于核保。

本地目录候选用于处理设备清单缺少后缀或版本的情况。例如 `JAM72D42-630W` 不会自动映射成 `JAM72D42-630/LB`；工作台会把后者列为待核对候选。只有铭牌确认完整型号后，才应将 `/LB` 型号重新查询并使用对应目录参数。若仍无法确认，保持未知并人工补材。

## 人工补正规则

工作台提交 `POST /api/v1/components/corrections` 前会要求：

- 填写完整型号、厂商、资料类型、原始资料 HTTPS 链接和复核人。
- 为每个非空参数提供字段级 HTTPS 来源。工作台录入的来源链接默认为已打开的 Datasheet 链接；若数值来自不同文档，应逐字段调整 API 请求中的 `parameter_sources`。
- 明确确认型号与铭牌/原始 Datasheet 一致，且参数单位及测试条件已经核对。

通过校验的补正保存在 `outputs/component-corrections.json`，可用 `PV_COMPONENT_CORRECTIONS_PATH` 指定其他路径。该文件受 `.gitignore` 保护，不应随仓库公开。下一次新案件查询会加载补正并只填充本地目录的空字段；已有目录中的非空数值不会被覆盖。发生数值冲突时返回 `409`，需要先人工核对资料、再通过版本控制维护正式目录。已经生成并保存的案件不会被回写，需重新分析才会使用新补正。

此接口记录的是“操作员已核对”的声明与来源，不等于系统独立验证了 PDF 内容。生产启用前，应由业务负责人规定复核人资格和目录变更审核流程。

## 参数与核保判断边界

- 风载/雪载需逐项区分厂家明示的设计值、测试载荷、安装方向及适用支架；正反面最大静载不得转换成项目设计风压或屋面雪荷载。
- 冰雹试验直径和速度需连同方法、版本及组件构型留存；不能只凭一个粒径值推断项目是否安全。
- Search leads 默认 `verified=false`，搜索结果不会参与当前案件的自动风险判断。
- 人工补正会用于后续案件的数据展示与灾害评估输入，但若风/雹/雪数据口径仍未验证，系统继续标记未知并转人工复核。

## 后续需要提供或完成

1. 若需要后台自动抓取网页搜索结果，申请 Brave Search API Key 并配置到本机 `.env` 的 `PV_COMPONENT_SEARCH_API_KEY`。没有 Key 时可用浏览器检索入口，但结果不会自动导入。
2. 在 Solar-Stack 或厂商官网找到型号后，将原始 Datasheet 里的参数、版本、单位、页码/测试方法和 HTTPS 源链接人工确认后录入。
3. `PV_COMPONENT_TRUSTED_SOURCE_DOMAINS` 是可选项：只有在希望某些域名优先检索时才填写。全网搜索结果即使找到参数，也必须打开原始 Datasheet、核对完整型号和条件后人工补正。
4. 提供官方组件数据包中可公开用于比赛的完整参数表和变更版本后，才能进一步批量扩展离线目录。

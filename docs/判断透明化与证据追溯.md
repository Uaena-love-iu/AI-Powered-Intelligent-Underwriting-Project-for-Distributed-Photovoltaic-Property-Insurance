# 判断透明化与证据追溯

## 用户可以追溯什么

系统结果页和 Markdown 报告都展示从输入到建议结论的路径：

1. 上传材料及材料包完整性检查。
2. OCR 字段、图像检查结果和识别不确定项。
3. 每份材料的审核动作、触发规则、关联 OCR 字段和图片证据。
4. 组件型号、参数逐项来源和试验条件；天气请求期、实际返回覆盖、有效日数、数据集、实际网格点和缺失灾种。
5. 自动处理步骤的 Provider、模型、状态、耗时和错误信息。
6. 整单汇总顺序、最终建议、参加汇总的规则及其中文解释。
7. 可选的地图辅助复核记录、地址匹配分数、复核人和地图影像日期（如果服务显示）。

拒保环境结果另外显示 `environment_relation`：项目现场本身、项目邻近周边、远处背景景物或现场关系不确定。只有环境关系列在业务配置的自动拒保范围内、参考置信度达到配置门槛且模型没有要求人工复核时，规则才自动给出拒保建议。当前配置只允许 `project_site` 自动拒保，默认置信度门槛为 0.65；该分数没有经过业务标注校准，不代表风险概率。相同配置同时提供给视觉模型作上下文，并由确定性规则再次检查；模型不能绕过规则配置给出最终拒保。邻近周边和不确定关系保留风险证据并转人工；远处背景保留记录但不触发现场拒保。邻近环境的正式边界尚未由业务确认，系统不设置虚构距离。业务确认边界后可在 `data/rules/challenge_open_ai_01.json` 配置邻近周边规则。

前端通过 `material_reviews.finding_ids` 和 `material_reviews.ocr_field_ids` 将单份材料动作连接到具体识别记录。规则详情来自 `decision.rule_explanations`；原始规则编号同时保留，方便定位配置和代码。

历史案件如果创建于规则说明字段上线之前，读取和人工复核接口会根据原始规则编号补齐中文说明，不要求重跑识别。

## 模型与程序规则的分工

OCR/视觉模型输出文字字段、图片观察、证据描述和参考分数。模型分数尚未经过概率校准，不能解释为某风险实际发生概率。模型也不直接输出整单承保结论。

规则引擎根据材料类别、识别状态、缺失字段、数据完整性和已配置业务规则生成逐项材料动作。多张全景的检查项按案件合并；前视图和俯视图可以互补。某一张全景没有返回一个检查项，不会单独触发补件；只有全部全景都缺少该项结果才要求补充对应视角或人工补录。明确的 `uncertain` 环境结果进入人工复核；图片质检明确发现模糊、过暗或关键区域不可见时才要求重拍。全景无水印在当前赛题阶段是非阻断提示，但水印已识别而拍摄日期无法核验，或日期超出拟起保日前 15 天，仍要求补充有效照片。

决策引擎按以下顺序选择整单建议：

> 建议拒保 → 位置冲突人工复核 → 补充材料 → 其他人工复核 → 建议加费 → 附条件承保 → 建议承保

因此，用户可以检查每一个动作是由哪条规则触发、规则查看了什么证据，以及该动作如何进入整单优先级。状态为 `warning` 且无需人工复核的提示（例如远处背景环境或当前阶段未提供水印）不会单独阻断建议承保；明确缺件、低质量材料、需要人工复核的规则或灾害参数缺失仍会按整单优先级转补件或人工审核。系统没有把未知状态当作已通过。

地图辅助复核是独立的人工外部参考：系统保存地址解析元数据和核保员手工观察，并明确标注“未作为自动规则事实”。“地图中未见”不能推导为现场没有光伏设施或没有风险。

## 规则说明维护

规则中文解释集中在 `backend/app/rules/explanations.py`，每条包括：

- 规则编号和标题。
- 触发条件。
- 对材料动作或后续流程的作用。

新增规则时，应同时增加规则逻辑、规则说明和测试。未登记的规则不会被隐藏：结果中会显示原编号和“规则说明待补充”。`tests/unit/test_rule_explanations.py` 会检查程序中的字面规则编号是否已有说明。当前灾害模块显示不具备可比口径的原因，不会用 10 米阵风动压、单独冰雹直径或单日降雪量伪装成工程能力比。

## 当前边界

透明展示说明的是“程序按当前实现为何给出建议”，不代表判断一定正确。高火险行业清单、正式业务规则表、邻近环境边界、比赛 C 包及 A/B/C 标注真值仍需补齐后，才能核实规则取值并评估真实识别准确率。业务规则发生变化时，应先更新配置和说明，再用标注材料回归验证。

# 图片初审链路的模型分工（2026-10-13）

本配置针对当前程序的图片核保初审链路。视觉模型负责提取可见事实、文字和证据；拒保、补材及人工复核动作由规则引擎汇总。模型能力不能仅凭厂商介绍推断为本赛题准确率，整案效果仍需使用有真值的样例核验。

| 环节 | 配置项 | 当前模型 | 选择依据 |
| --- | --- | --- | --- |
| 上传后的图片材料分类 | `PV_VLM_CLASSIFICATION_MODEL` | `qwen3.7-flash` | 用户可复核并改类，优先考虑响应速度与成本。 |
| 备案类材料的早期 OCR | `PV_VLM_FILING_MODEL` | `qwen3.8-max` | 提取字段会进入备案禁投规则；尽量降低关键文字误读。 |
| 普通业务文字、水印、铭牌 OCR | `PV_VLM_OCR_MODEL` | `qwen3.7-flash` | 结果仍以原图为准，字段缺失会走补材或人工复核。 |
| 多图安装类型及承保范围确认 | `PV_VLM_INSTALLATION_MODEL` | `qwen3.8-max` | 可能直接排除地面式等范围外结构，是高影响判断。 |
| 单图风险识别 | `PV_VLM_VISION_MODEL` | `qwen3.8-max` | 部分风险会直接触发拒保规则，应优先保证证据质量。 |
| 后置倾角、离地高度和地面粗糙度粗估 | `PV_VLM_GEOMETRY_MODEL` | `qwen3.7-flash` | 仅生成带证据的候选；当前灾害公式尚未直接使用这些粗估值。 |
| 完整性、承保规则、灾害计算、整单建议 | 不调用此视觉模型 | 程序规则和数据服务 | 保持动作可复核，不让视觉模型直接生成核保结论。 |

`PV_VLM_MODEL=qwen3.7-flash` 是未配置专用变量时的回退模型。模型名只在服务端配置；实际调用型号会进入处理留痕和报告。`/ready` 返回不含密钥的 `model_routing`，可核对启动后的分工。

两个启动入口读取同一份项目模型分工：`start_workbench.py` 使用项目 `.env` 的 API Key；`run_evaluation.py` 使用本机共享配置中的 API Key。两把密钥不同，均已通过 `qwen3.7-flash` 和 `qwen3.8-max` 的最小文本调用验证；额度会随使用变化。

2026-10-13 的小范围真实接口验证使用项目测试素材：3.7-Flash 与 3.8-Max 均能完成材料分类；3.8-Max 能返回备案字段、车棚顶组图类型及单图风险 JSON；3.7-Flash 能返回铭牌字段和几何候选。该验证只证明接口和现有结构化协议可以工作，不等同于整案通过率或拒保准确率。完整案件由使用者试跑。

阿里云文档确认两类模型支持图像输入和结构化输出：[视觉理解模型](https://help.aliyun.com/zh/model-studio/vision-model/)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。北京地域原价参考：[模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。3.7-Flash 在单次输入不超过 32K Token 的档位为输入 0.2 元、输出 0.8 元／百万 Token；3.8-Max 为输入 12 元、输出 36 元／百万 Token。实际账单受图片 Token、输入长度、地域、缓存和活动价格影响。
